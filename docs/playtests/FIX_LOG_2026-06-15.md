## Fixes

### F0 — harness fidelity: strip `Wizard:` speaker prefix
`scripts/dm-playtest.mjs`. The UI renders the DM via speaker attribution; the literal
`Wizard:` prefix on engine base narration is never shown to a player. The harness was
feeding it to the judge, reading as a system-artifact leak (NB-7). Stripped in `playTurn`.

### F1 — CANON_HALLUCINATION: canon-grounded proper-noun guard ✅
**Root cause:** `validateNarrationCandidate` had its new-noun heuristic removed (llmAdapter.js:241,
"the system prompt already constrains invention") — but the gate proved the Sonnet polish invents
NPC/place names anyway ("Senna the Elder", "Ferry Landing", "Aldren"). This is the root of several
downstream fails too (LH "success but no payoff" turns were the DM unable to ground names it had
earlier invented).

**Fix (`engine/llmAdapter.js`):**
1. Strengthened the system prompt: explicit rule against naming any person/place/thing whose proper
   name isn't already in the canon facts; refer to others generically.
2. Reinstated a backstop in `validateNarrationCandidate`: `collectGroundedNouns()` builds the allow-set
   from the engine base text + place + NPCs present + speaker + place history + ledger + map nodes;
   `findInventedProperNoun()` rejects any candidate with a name-like capitalized token not in that set
   (handles possessives, quoted spoken names, sentence-initial caps, common words/titles/interjections).
   On reject the narration falls back to the engine base text — **always grounded, never throws.**

**Tests:** new `tests/U142.narrationGroundsProperNouns.test.js` (8 cases, incl. the three real
inventions + grounded passes). Full suite **7633 green**; `prose:gate` **PASS** (216/0).
Live-confirmed the bug pre-fix via direct `/api/narrate` probe (polish invented "Senna the Elder"/
"Ferry Landing" from a plain base line).
