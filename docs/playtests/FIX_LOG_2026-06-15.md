## Fixes

### F0 — harness fidelity: strip `Wizard:` speaker prefix
`scripts/dm-playtest.mjs`. The UI renders the DM via speaker attribution; the literal
`Wizard:` prefix on engine base narration is never shown to a player. The harness was
feeding it to the judge, reading as a system-artifact leak (NB-7). Stripped in `playTurn`.

### F1 — CANON_HALLUCINATION: canon-grounded proper-noun guard ✅
**Root cause:** `validateNarrationCandidate` had its new-noun heuristic removed (llmAdapter.js:241,
"the system prompt already constrains invention") — but the gate proved the Sonnet polish invents
NPC/place names anyway ("Senna the Elder", "Ferry Landing", "Aldren"). This is the root of several
downstream fails too (LH "success but no payoff" turns were the DM unable to ground names it had
earlier invented).

**Fix (`engine/llmAdapter.js`):**
1. Strengthened the system prompt: explicit rule against naming any person/place/thing whose proper
   name isn't already in the canon facts; refer to others generically.
2. Reinstated a backstop in `validateNarrationCandidate`: `collectGroundedNouns()` builds the allow-set
   from the engine base text + place + NPCs present + speaker + place history + ledger + map nodes;
   `findInventedProperNoun()` rejects any candidate with a name-like capitalized token not in that set
   (handles possessives, quoted spoken names, sentence-initial caps, common words/titles/interjections).
   On reject the narration falls back to the engine base text — **always grounded, never throws.**

**Tests:** new `tests/U142.narrationGroundsProperNouns.test.js` (8 cases, incl. the three real
inventions + grounded passes). Full suite **7633 green**; `prose:gate` **PASS** (216/0).
Live-confirmed the bug pre-fix via direct `/api/narrate` probe (polish invented "Senna the Elder"/
"Ferry Landing" from a plain base line).

### F2 — CRUNCH_INCONSISTENCY: self-harm deals a wound ✅
**Reproduced:** "cut my own forearm" → `trivial action — no roll, auto-success`, **0 wounds**;
"stab myself" → routed through a *fail-able* skill check (rolled a failure, "you're left where
you started"). Both wrong — you cannot fail to cut yourself, and it is never a no-effect action.

**Fix (`engine/playloop.js`):** new `trySelfHarm` gate before the trivial-intent gate. A harm verb
(cut/stab/slash/…) + an explicit self target (myself / my own / my arm…), not negated, resolves as
a deterministic `{op:'wound', by:1}` via `applyDeltas` — no DC, no roll. Caps gracefully at max
wounds. Negation/hypothetical guard ("threaten to", "almost", "as if") keeps false positives out.

**Tests:** new `tests/U143.selfHarmDealsWound.test.js` (4 cases incl. external-target + hypothetical
negatives). Verified live: "cut the rope" / "draw my sword" / "threaten to cut myself" / "almost cut
my hand" all correctly avoid the gate. Suite **7637 green**; `prose:gate` **PASS**.

### F3 — DM_TEST_DEADEND: equipment/sheet queries answered without a dice roll ✅
**Reproduced:** "name my weapon" / "what's on my character sheet" fell through grace to a fabricated
social d20 roll (`[roll:13 vs DC:12 → mixed | stake:reputation]`) — an information request resolved as
a contest. The polish then *invented* "a short sword" (the PC actually has none).

**Fix (`engine/grace/gracefulAdjudication.js`):** new `META_EQUIPMENT` pattern + handler. Equipment/
wielding/wearing/sheet queries are recognized as meta-questions (no roll, no turn, no mutation) and
answered in-voice from real canon — weapons/armor named if present, an empty loadout reported honestly
("you bear no weapon worth the name"). HP queries already worked via `META_HEALTH` (in-voice; numeric
HP doesn't exist in this system — that judge flag was a non-bug per THE_DM_TEST).

**Tests:** new `tests/U144.equipmentQueryGrace.test.js` (4 cases). Suite **7641 green**; `prose:gate` PASS.

> **⚠ Content gap found (punchlist, NOT fixed here — touches chargen + worldHash):** the starting
> Sellsword "Nyx" has an **empty weapon/armor loadout**, `dnd:null`, and a signature item literally
> named **"Thing"**. A sellsword with no sword is absurd and is *why* the DM kept inventing a weapon.
> Chargen should grant a starting loadout. Logged for the punchlist.

### F4 — COMBAT_NOT_STARTED: natural-language attacks start real combat ✅
**Reproduced:** "I grab the nearest chair and swing it at Corwin's head" → `trivial action —
auto-success` KO, **no combat, no enemy, no HP** (high sev; confirms crotchety-dm #7). Two root
causes: (1) the combat-begin detector required the target to immediately follow the verb, so an
object between them ("swing **it** at X") never matched; (2) `fuzzyMatchNpc` couldn't match
"Corwin's head" to "Corwin Boneknit" (no shared substring).

**Fix (`engine/playloop.js`):**
- Broadened `detectAttackAnyIntent`: an aggression preposition ("…at/into/against <ref>"), direct
  verb-object ("punch the guard"), and attack idioms ("come at / lunge at / set upon") each yield a
  target ref; every ref must still resolve to a PRESENT NPC, so objects ("smash the barrel") and
  friendly acts ("throw a coin to Corwin") never trigger combat. Feeds the same `beginCombat` path.
- Added token-level name matching to `fuzzyMatchNpc` ("Corwin's head" -> "Corwin Boneknit").
- Moved the self-harm gate (F2) to run BEFORE combat-begin, so "stab myself" can't be read as an
  attack on a present NPC.

**Verified:** swing-at / punch / lunge-at / come-at -> combat; "throw a coin to Corwin", "smash the
barrel", "swing the door open" -> not combat; "cut the rope" / "stab myself" unaffected. Tests: new
`tests/U145.narrativeAttackStartsCombat.test.js` (5 cases); existing W-01 / UX2-W stay green. Suite
**7646 green**; `prose:gate` PASS.

**Known limits (punchlist):** (a) "go for X" doesn't trigger — "go" is consumed by the movement gate
(runs before combat-begin). (b) Throwing an object AT an NPC routes to the gratuitous-innocent-harm
*consequence* system rather than combat — a real consequence, but inconsistent with "swing at" ->
combat; worth unifying later.

### F5 — DM_ARTIFACT_LEAK: missing articles in the "look for X, but what's here is…" pivot ✅
**Reproduced:** "examine the door" (no door present) → "…what's here is **straw pallet, wooden table,
and wooden chair**" — missing articles read as garbled machine output.

**Fix (`engine/playloop.js`):** prepend a/an to each furniture name in the pivot list →
"…what's here is **a straw pallet, a wooden table, and a wooden chair**." Suite **7646 green**;
`prose:gate` PASS (the corpus line now reads correctly).

### F6 — CANON_HALLUCINATION: interior survey acknowledges the living settlement ✅
**Reproduced (both runs):** newbie "where am I?" inside the starting building → "You're inside X. **No
one else is under this roof.**" while seven NPCs stand in the settlement — reads as an unsupported
"alone in an empty world" claim. **Fix (`engine/grace/gracefulAdjudication.js`):** when inside a
structure in a peopled settlement, the survey now adds "…though you can hear the settlement stirring
beyond the walls" (honest sight-scoping: you hear, not see, them). Suite **7646 green**; `prose:gate` PASS.

### Investigated, deferred to punchlist (NOT safe to do autonomously)
- **Starting loadout (#2):** confirmed a *wiring* bug — `packs/fantasy/gear.json` (full weapon/armor
  tables w/ damage dice) is **never loaded**; `beginAdventure` calls `createCharacter` with no

## Tackling punchlist #1 — combat-from-narrative breadth

### F8 — physical assaults on a present NPC start real combat ✅
**Reproduced (classified the whole family):** clean verb-object attacks (`tackle`/`behead`/`punch`) and
`swing X at <NPC>` (F4) already started combat, but the chaos persona's other violence routed to a
*consequence-free skill roll* (`shove X into the shelf`, `press dagger to throat`, `drag X as a shield`)
or the *offensive-cast innocent-recoil* path (`throw/hurl X into/through Y`). All "zero mechanics."

**Fix (`engine/playloop.js`):**
- New `detectPhysicalAssault` — four frames, each requiring a **present-NPC** target (so objects and
  benign uses fall through): (A) inherently-violent grapples (choke/strangle/wrestle/pin/headbutt/…),
  (B) forced-into-harm (`shove|throw|hurl|slam|drag … <NPC> into|onto|against|through|over …`, excluding
  `past|aside|away`), (C) a blade brought **to the body** (weapon noun + aggressive verb + to/against
  `<NPC>`, so "give the dagger to X" doesn't trip), (D) hostage/human-shield grabs.
- Gate placed **before** the offensive-cast recoil gate, so PHYSICAL violence fights while offensive
  **spells** at innocents still recoil ("gratuitous magic has consequence" — preserved).
- Extracted `engageNpcCombat()` (mint enemy → beginCombat → resolve opening move → log + compose) and
  refactored the existing CM11 attack-any path onto it (no duplication; behavior unchanged).

**Verified:** 7/7 violent phrasings → combat; 6/6 benign (`shove past`, `grab a cup`, `give/throw the
dagger to X`, `throw a coin to X`, `throw my pack onto the table`, `walk over to X`) → no combat. Tests:
new `tests/U147.physicalAssaultStartsCombat.test.js` (3 cases). Suite **7650 green**; `prose:gate` PASS.

### Still open — combat **lifecycle** depth (deferred, not safe autonomously)
The opening assault now lands as combat. The remaining incoherence is multi-turn: a weak townsperson
**yields after one exchange** (combat ends with them hurt-but-alive — arguably correct DM behavior), and
follow-ups against a *yielded/downed* NPC ("stab him again", "behead him") fall to a generic roll or
empty resolution. That's combat-lifecycle work (re-engage a yielded foe, coup-de-grace a downed one) —
needs live-play validation, left for a focused packet.

### Measured: focused chaos-persona run (2 seeds × 12 turns) — **15/24 failing (63%)**, $1.25
F8 is confirmed a real but *partial* first step. The chaos rampage exposed combat-from-narrative as a
**multi-part packet** (now decomposed as punchlist 1a–1d):
- **1a initiation breadth** — F8 covers the main family; still uncaught: `drive my knee into`, `bite`,
  `headbutt … out from under`, and multi-action lines ("grab X **and** slam his head into Y").
- **1b mid-combat lifecycle** — switching targets, re-engaging a yielded foe, finishing a downed NPC.
- **1c PC death/defeat state (sharp, root-caused here):** driving combat in-process, the PC hits the
  wound cap (7 wounds, fighting bare-handed — the empty-loadout gap #2 makes combat very lethal), the
  engine narrates **"You fall in the fight"** but sets **no defeat/death state and never ends the
  encounter** — combat flips off, `ending.locked` stays false, and every subsequent input **replays the
  death line** while `party[0].wounds` stays 7 and no `defeated` flag is set. Narration says dead, canon
  says alive. Design-laden (death semantics in the *Immortal* Engine) and in the **non-escape** combat
  path (live surface is `escapeCombat` — the two-engines gotcha). **Not safe to change autonomously.**
- **1d hazard mechanics** — fire spread / arson / knocking over a brazier: narrated, zero effect.

Stopping combat work here: 1b–1d need design decisions + live escape-mode validation with Tim in the
loop. F8 (initiation breadth) stands as the safe, tested, committed first step.

### F9 — harness fidelity: the gate now boots ESCAPE MODE (the live combat engine) ✅ — **reframes #1**
**The catch:** `public/v1.js` boots every new game with **`mode:'escape'`** (line 338) — which selects the
`escapeCombat` engine (`meta.escapeHp`, a real **loss-ending on defeat**). The gate booted in the default
mode `''`, exercising the **non-escape** `resolveCombatTurn` engine instead. **The combat half of every
gate run was unfaithful** — a different engine than players hit. (Non-combat findings F1–F7 are unaffected:
narration/grace don't depend on combat mode.)

**Fix (`scripts/dm-playtest.mjs`):** boot `newWorld({ …, mode:'escape' })` to match v1.

**Re-measured (chaos persona, 2 seeds, escape mode): 8/24 (33%) — down from 63%.** Escape mode is far more
coherent: `escapeHp 13/13` inits, "attack the innkeeper" runs real rounds (`[combat:r2]`, HP 13→11) →
`[combat:victory]`. **The PC death-loop (1c) does NOT occur in the live game** — escapeCombat locks a proper
loss-ending; the loop was a non-escape artifact. That removes the scariest item from #1.

**Reframed remaining combat work (escape mode, the real picture):**
- **1b mid-combat target-switching (now the dominant real issue)** — attacking a *new* present NPC mid-fight
  ("lunge at Petra" while fighting Senna) never instantiates Petra as a combatant; the swing resolves to
  pure narration. Tractable: add the new target as an enemy when attacked mid-combat.
- **combat narration vs dice** — a NAT20 'defeat' narrated as the foe still standing (composer/polish not
  honoring the mechanical result).
- **1d spell/cantrip at objects/hazards** — "hurl a firebolt at the wagon" → no fire/damage outcome.
- **mid-combat non-attack actions** ("plant boot on chest and demand…") resolve with no contest.
- **1a residue** — `drive my knee into`, `bite`, multi-action lines still uncaught at initiation.

**Caveat for the engine-minded:** combat-BEGIN (F8/CM11 `engageNpcCombat`) still uses the non-escape
`beginCombat`+`resolveCombatTurn` for turn 1 even in escape mode; turns 2+ route to `resolveEscapeCombatTurn`.
Escape mode mostly absorbs this, but routing combat-begin through the escape path in escape mode is the
clean reconciliation (a focused engine task — validate live).

### F10 — 1b: mid-combat target-switching ✅
**The dominant real combat failure (escape mode):** attacking a NEW present NPC mid-fight ("lunge at
Petra's throat" while fighting Senna) never instantiated Petra as a combatant — the escape resolver only
knows the existing enemies, so the strike resolved to pure narration.

**Fix (`engine/playloop.js`):** new `detectNewCombatTarget` — when combat is active and the input is an
aggressive line that **explicitly names a present, non-enemy NPC**, mint them via `mintEnemyFromNpc`
(unique `id`, `hp` from `maxHp`) and add them through the canonical `combatState` delta **before**
`resolveEscapeCombatTurn` resolves the round (which then targets the named foe). Conservative by design:
fires only on an explicit name token, so "stab him again" (the current foe), attacking the current enemy
by name (no duplicate), and table-talk all add no one.

**Verified:** mid-fight `lunge at <B>` / `drive my blade into <B>'s gut` add B and the round resolves
(`[combat:r2]`); the three negative cases add nothing. Tests: new `tests/U148.midCombatTargetSwitch.test.js`
(4 cases). Suite **7657 green**; `prose:gate` PASS.
