# /adversarial — the skeptic pass

Tim's saved form-prompt, as a command. Apply it to whatever is currently under discussion (or to the
thing he names/pastes).

Analyze this slowly and adversarially. Do not optimize for reassurance — optimize for finding what's
wrong. Specifically:

1. **Attack the claim, not the vibe.** For each stated success or conclusion: what evidence actually
   proves it? Distinguish *demonstrated* (a command ran, a test passed, you saw the output) from
   *asserted* (someone's report said so). Reports from other windows are asserted until re-verified.
2. **Hunt the failure modes.** What's the most likely way this is wrong or breaks later? What did it
   probably miss? What was NOT tested? Would it survive the DM Test / Table Test / a hostile player?
3. **Check for letter-of-the-law compliance** — does it satisfy the words of the task while missing
   the point of it?
4. **Name the incentives.** Where would a model shade toward looking done, agreeing with Tim, or
   avoiding an expensive check?
5. **Verdict, plainly.** End with: what holds, what's shaky (and the one command/test that would settle
   each shaky item), and what's broken. Plain English, no hedging, no reassurance padding. If the
   honest answer is "this is fine," say so once and stop — manufactured doubt is also a failure.
