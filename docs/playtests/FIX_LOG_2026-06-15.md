## Fixes

### F0 — harness fidelity: strip `Wizard:` speaker prefix
`scripts/dm-playtest.mjs`. The UI renders the DM via speaker attribution; the literal
`Wizard:` prefix on engine base narration is never shown to a player. The harness was
feeding it to the judge, reading as a system-artifact leak (NB-7). Stripped in `playTurn`.

### F1 — CANON_HALLUCINATION: canon-grounded proper-noun guard ✅
**Root cause:** `validateNarrationCandidate` had its new-noun heuristic removed (llmAdapter.js:241,
"the system prompt already constrains invention") — but the gate proved the Sonnet polish invents
NPC/place names anyway ("Senna the Elder", "Ferry Landing", "Aldren"). This is the root of several
downstream fails too (LH "success but no payoff" turns were the DM unable to ground names it had
earlier invented).

**Fix (`engine/llmAdapter.js`):**
1. Strengthened the system prompt: explicit rule against naming any person/place/thing whose proper
   name isn't already in the canon facts; refer to others generically.
2. Reinstated a backstop in `validateNarrationCandidate`: `collectGroundedNouns()` builds the allow-set
   from the engine base text + place + NPCs present + speaker + place history + ledger + map nodes;
   `findInventedProperNoun()` rejects any candidate with a name-like capitalized token not in that set
   (handles possessives, quoted spoken names, sentence-initial caps, common words/titles/interjections).
   On reject the narration falls back to the engine base text — **always grounded, never throws.**

**Tests:** new `tests/U142.narrationGroundsProperNouns.test.js` (8 cases, incl. the three real
inventions + grounded passes). Full suite **7633 green**; `prose:gate` **PASS** (216/0).
Live-confirmed the bug pre-fix via direct `/api/narrate` probe (polish invented "Senna the Elder"/
"Ferry Landing" from a plain base line).

### F2 — CRUNCH_INCONSISTENCY: self-harm deals a wound ✅
**Reproduced:** "cut my own forearm" → `trivial action — no roll, auto-success`, **0 wounds**;
"stab myself" → routed through a *fail-able* skill check (rolled a failure, "you're left where
you started"). Both wrong — you cannot fail to cut yourself, and it is never a no-effect action.

**Fix (`engine/playloop.js`):** new `trySelfHarm` gate before the trivial-intent gate. A harm verb
(cut/stab/slash/…) + an explicit self target (myself / my own / my arm…), not negated, resolves as
a deterministic `{op:'wound', by:1}` via `applyDeltas` — no DC, no roll. Caps gracefully at max
wounds. Negation/hypothetical guard ("threaten to", "almost", "as if") keeps false positives out.

**Tests:** new `tests/U143.selfHarmDealsWound.test.js` (4 cases incl. external-target + hypothetical
negatives). Verified live: "cut the rope" / "draw my sword" / "threaten to cut myself" / "almost cut
my hand" all correctly avoid the gate. Suite **7637 green**; `prose:gate` **PASS**.

### F3 — DM_TEST_DEADEND: equipment/sheet queries answered without a dice roll ✅
**Reproduced:** "name my weapon" / "what's on my character sheet" fell through grace to a fabricated
social d20 roll (`[roll:13 vs DC:12 → mixed | stake:reputation]`) — an information request resolved as
a contest. The polish then *invented* "a short sword" (the PC actually has none).

**Fix (`engine/grace/gracefulAdjudication.js`):** new `META_EQUIPMENT` pattern + handler. Equipment/
wielding/wearing/sheet queries are recognized as meta-questions (no roll, no turn, no mutation) and
answered in-voice from real canon — weapons/armor named if present, an empty loadout reported honestly
("you bear no weapon worth the name"). HP queries already worked via `META_HEALTH` (in-voice; numeric
HP doesn't exist in this system — that judge flag was a non-bug per THE_DM_TEST).

**Tests:** new `tests/U144.equipmentQueryGrace.test.js` (4 cases). Suite **7641 green**; `prose:gate` PASS.
